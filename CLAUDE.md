# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Source of [budovatel.cz](http://budovatel.cz/) — a Jekyll 4.4 static site (Ruby 3.4, pinned in `.ruby-version`), with the minima theme and kramdown, deployed by Netlify on push to `master`. It archives Czech/Slovak socialist-era songs, poems, articles and pictures. All content and UI text is in Czech. There are no tests, linters or CI.

## Commands

```sh
bundle install
bundle exec jekyll serve     # local preview at http://localhost:4000 (restart after editing _config.yml)
bundle exec jekyll build     # output to _site/ (gitignored)
```

The system Ruby on the maintainer's Mac is too old; build in Docker instead:

```sh
docker run --rm -v "$PWD":/srv -w /srv ruby:3.4.8 bash -c 'bundle config set --local path vendor/bundle && bundle install && bundle exec jekyll build'
```

Sheet music sources are LilyPond files in `noty/lylipond/` (all compile without warnings in LilyPond 2.24 — check without `-s`, which hides warnings; outputs in `noty/{jpg,midi,pdf,ps}` are pre-rendered and committed). To compile one:

```sh
printf 'FROM debian:bookworm-slim\nRUN apt-get update && apt-get install -y --no-install-recommends lilypond\n' | docker build -t budovatel-lilypond -
mkdir -p /tmp/ly && docker run --rm -v "$PWD/noty/lylipond":/w:ro -v /tmp/ly:/out budovatel-lilypond lilypond -o /out/Nazev /w/Nazev.ly   # absolute paths: -o changes cwd
```

Per-song web files (`noty/jpg/<song>.png` cropped notes image, `noty/pdf`, `noty/ps`, `noty/midi`) are regenerated from the `.ly` sources by `noty/build_noty.sh` (Docker); five MIDI files with orchestral arrangements are kept as they are. Song pages find these files by exact basename (`_includes/soubory.html`) and show the notes image, an html-midi-player and an MP3 player inline.

The printable songbook `noty/pdf/Budovatel_zpevnik.pdf` is generated by `noty/zpevnik/build.sh` (python3 + Docker): it merges every `noty/lylipond/*.ly` into one LilyPond book with a title page, foreword and contents, adds the stanzas from `_pisne/` that are not already under the notes, and writes `_data/zpevnik.yml` (song → PDF page) used for the "Ve zpěvníku" links. A GitHub Actions workflow (`.github/workflows/noty.yml`) runs `noty/build_noty.sh` and `noty/zpevnik/build.sh` on every push that touches `noty/lylipond`, `noty/zpevnik` or `_pisne` and commits the results back to `master`, so after pushing a song change pull before editing further. Both scripts use an installed LilyPond 2.24 if present, otherwise Docker (`noty/lilypond.sh`); the songbook is only rebuilt when its generated source changes (`noty/zpevnik/zdroj.sha`), because PDFs embed random IDs. `python3 noty/zpevnik/verses.py` lists the extracted stanzas for checking.

## Architecture

Nearly all work is adding content files; commits are typically just a new `.md` named after the piece.

### Collections (`_config.yml`)

| Folder | Layout | URL | Front matter |
|---|---|---|---|
| `_pisne` (songs) | `pisen` | `/pisen.phtml/:title` | `title`, `obdobi`, `music`, `text`, `preklad`, `youtube` |
| `_poezie` (poems) | `poezie` | `/poezie.phtml/:title` | `title`, `autor`, `vydal`, `rok`, `youtube` |
| `_state` (articles) | `poezie` | `/state.phtml/:title` | `title`, `autor`, `vydal`, `rok` |
| `_obrazky` (pictures) | `obrazek` | `/obrazky.phtml/:title` | `name`, `autor`, `galery: true` |

- Every person field (`music`, `text`, `preklad`, `autor`) may be a YAML list when there are several people; templates normalize it with `join: "|" | split: "|"` and `_includes/jmena.html` renders the linked names.
- `vydal` is the publication title only (no year, no leading "časopis"), the year goes to `rok` (a quoted string, may be `"cca 1953"` or `"1957?"`), so all issues of one magazine group together on `vydal.phtml`.
- Links to collection pages are emitted lowercased (`| downcase`) because Netlify 301-redirects mixed-case URLs to lowercase.
- `_plugins/pridano.rb` sets `page.pridano` (date the file first appeared in git history, renames keep the date) for all four collections; `znarodneno.phtml` ("Nově znárodněno") and the homepage list items by it, newest first.
- `_plugins/ceske_razeni.rb` provides the Czech-alphabet sort filters used by `autori.phtml` and `vydal.phtml`; `hledat.html` searches `search.json` client-side; `sitemap.xml` and `robots.txt` are Liquid templates.
- `obdobi` is a period id from `_data/obdobi.yml` (nejstarsi … normalizacni); the song list `pisne.phtml` groups songs by it in that order and the song page links to its section. Every song should have one.
- `youtube` is just the video ID (rendered by `_includes/youtube.html`).
- Filenames are ASCII with accents stripped and spaces as `_` (e.g. `Armade_zdar.md`); some older entries are `.html`.
- Song/poem bodies are Markdown where each verse line ends with two trailing spaces to force a line break — preserve them.
- The `*.phtml/index.html` directories are the listing pages (the `.phtml` names preserve URLs from the original PHP site). `autori.phtml` and `vydal.phtml` build author/publisher indexes by collecting the `music`/`text`/`preklad`/`autor`/`vydal` values across collections, so these front-matter values must be spelled identically across entries to group together.

### Static-file matching by filename

Media are linked automatically, not via front matter:

- `_includes/media.html` (used by `pisen`/`poezie` layouts) finds files in `noty/{jpg,midi,mp3,ps,pdf,lylipond}` whose name matches the page id (e.g. `noty/midi/Armade_zdar.midi`, `noty/lylipond/Armade_zdar.ly`). The `_config.yml` defaults tag those folders with flags (`midi: true`, …) that the include filters on. Sheet-music images in `noty/jpg` are `.gif`.
- `img/` is organised as `vzhled/` (header/navigation graphics, title picture), `galerie/<Page_name>/` (galleries), `obrazky/` (single pictures of `_obrazky` pages) and `pisne/`, `poezie/`, `state/` (illustrations used inside texts). The `obrazek` layout with `galery: true` shows every file in `img/galerie/<page title>/` with the bundled `unitegallery` jQuery plugin. Old image URLs are 301-redirected in `netlify.toml`. Gallery thumbnails live in `img/nahledy/<Page_name>/` and are generated by `img/nahledy.py` (Pillow); the `nahledy.yml` workflow regenerates and commits them on every push touching `img/galerie`, and the layout falls back to the full image when a thumbnail is missing.

### Layout and mobile

The retro look is fixed-width tables (680 px header/navigation image strips). Below 720 px (`@media` block in `_includes/head.html`) the header and navigation images scale to the screen width and two-column layout tables marked `class="sloupce"` stack vertically; keep that class on new layout tables. `patrame.html` lists songs readers are looking for. Every page ends with the copyright notice `_includes/autorska_prava.html` (included in `_layouts/default.html`).

### Netlify

`netlify.toml` holds only redirects for renamed pages (keep old URLs working when renaming a content file); build command and publish dir are set in the Netlify UI.
